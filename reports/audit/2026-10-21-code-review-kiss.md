# Ревью mvr: переусложнение и «наращивание вместо переписывания»

Дата: 2026-10-21 · объём: src/lib.rs (976, из них ~415 тесты), src/tui.rs (559),
src/main.rs (187), tests/cli.rs, scripts/mvr_pty_check.py · фокус по запросу:
KISS > DRY, переусложнение, аккумулирование функционала поверх старой структуры.

## Вердикт

Кодовая база — честная KISS для своих ~1200 строк без тестов: нет лишних
абстракций, нет преждевременной обобщённости, `exists` инъектируется для тестов,
ошибки — enum с человеческим Display, тесты отличные (45 юнит + интеграционные
+ живой pty-смоук). История показывает, что проект реально переписывал, а не
только латал: `cd6278a` (сегментный матчинг, +493/−149), `3c28d2c` (выкинут
флаг `-r`), `e1fe602` (сканер переписан под match-driven walk), `5484303`
(выкинут фоновый тик). Классическая болезнь «фичи поверх трупа старого дизайна»
почти отсутствует — нашлись четыре локальных очага и один живой баг строки.

## Что специально НЕ трогать (проверенные подозреваемые)

| Подозрение | Почему это ок |
|------------|---------------|
| Две функции пруна: `planned_prunes` (lib.rs:456) и `prune_emptied_dirs` (lib.rs:498) | Это не дубль, а предсказание vs реальность: первая чистая, работает по списку скана для dry-run; вторая смотрит на диск (`dir_is_empty`) и терпит частичные отказы apply. Слить их — привязать чистую функцию к диску или фейкать его в тестах. Общий скелет «очередь вверх по дереву» — приемлемая цена. |
| Кэш сканера (lib.rs:10) + контракт «F5/apply перечитывают» | Осознанное решение, закреплено тестами (`scanner_cache_stays_stale_until_forced`, pty-кейсы `cache:`/`no tick:`) и README. 80 строк, выполняют работу. |
| Hand-rolled `Input` (tui.rs:32) | 70 строк, ноль зависимостей, читается как книга. `tui-input`-крейт здесь был бы хуже по метрике «сложность = код, который поддерживаешь ты». |
| Двойная проверка цели: `TakenTarget` в plan + `to_path.exists()` в apply (lib.rs:431) | Defense in depth против TOCTOU, явно заявлен в README. Это не дубль, это два момента времени. |
| `plan` / `plan_outcome` параллельно | Само по себе ок — 4 строки обёртки. Проблема в сигнатуре, см. находку 4. |
| `summarize` (tui) vs `finish` (main) | Дублирование есть, но раковины разные (одна зелёная строка TUI против stdout/stderr-стримов CLI). Общая хелпер-функция потребовала бы структуру — не очевидно проще. Под KISS «дважды простое» допустимо. |

## Наращивание вместо переписывания — детально

### 3. Vestigial `poll(250ms)` — структура пережила свою причину

`tui.rs:160`: `if !event::poll(Duration::from_millis(250))? { continue; }`.

Таймаут-цикл существовал для 2-секундного фонового тика плоского списка.
Коммит `5484303` тик удалил (условие с `Instant::elapsed` выпилено — видно в
диффе), но скелет poll+continue остался. Теперь по таймауту loop делает один
холостой проход: проверка scan_key (no-op) → draw (ratatui диффает, дёшево, но
4 раза в секунду впустую). По `.continue` на таймауте живёт и импорт `Duration`.

Фикс: `let event = event::read()?;` — блокирующее чтение, минус таймаутная
ветка. Это ещё и каскад: с блокирующим read каждая итерация цикла следует за
реальным событием, значит флаг `rebuild` и `view: Option<View>` (tui.rs:136-137,
154-157, 274) тоже становятся мёртвой структурой — build_view можно звать в
каждой итерации безусловно, той же стоимости, что сейчас (сейчас он и так
выполняется на каждое событие). Машины меньше, поведение то же.

### 4. Сигнатура `plan_outcome` — двойная работа в обоих лицах и порядок ошибок в CLI

`plan_outcome` (lib.rs:302) принимает сырые `paths` и сам зовёт `match_paths`
(lib.rs:319). Коммит `e494038` извлекал его из `plan` для TUI («keep preview on
plan errors»), но сохранил самодостаточную форму исходной функции вместо того,
чтобы перевернуть контракт: план строится из УЖЕ сматченных путей.

Последствия:

- **CLI** (main.rs:87-95): `plan(...)` гоняет `match_paths` внутри, затем
  `match_paths(&paths, &matchers).is_empty()` — второй раз, ради «nothing found».
  Бонус-варт: проверка «nothing found» стоит ПОСЛЕ plan, поэтому `mvr 'zzz' 'v$2'`
  на непустом каталоге напечатает ошибку про `$2`, а не «nothing found» —
  пользователь опечатался в regex, а ему про группы.
- **TUI** (tui.rs:308 + 331): `match_paths` для списка «old», затем
  `plan_outcome` повторяет его внутри — на каждое нажатие клавиши. Туда же:
  `compile_matchers` дважды на каждое изменение regex (tui.rs:144 в run-loop +
  tui.rs:298 в build_view).

Фикс-форма: `plan`/`plan_outcome` принимают `&[MatchedFile]` (matchers остаются
в аргументах — нужны для `captures_len` в валидации групп). Тогда CLI зовёт
`match_paths` один раз, проверяет `matched.is_empty()` ДО планирования (заодно
чинит порядок ошибок), TUI передаёт уже готовый список из build_view.

### 5. TUI `conflicting()` — третья копия знания о конфликтах, и она уже разошлась с планом

Знание «цель плохая» живёт в трёх местах: `validate_targets` (lib.rs:357,
решает SameTarget/TakenTarget/ChainedTarget/TargetInsideSource), план-ошибка —
первая найденная, а TUI для покраски строк пересобирает его самостоятельно:
`tui.rs:342-347` (`target_counts` + `exists`). Это аккумулирование: `PlanOutcome`
получил поле `error` (первая ошибка целиком), вместо того чтобы нести статус
по-строчно, и подсветку достроили рядом своим детектором.

Живая цена расхождения уже есть: план `d/x => d/x/y` (TargetInsideSource,
lib.rs:380) в TUI красится **зелёным** — `conflicting("d/x/y")` проверяет
only count>1 и exists(), а `d/x/y` не существует (x — файл). Пользователь видит
зелёную строку и красную ошибку под ней про то же самое. ChainedTarget,
кстати, красится красным случайно — через exists().

Варианты:
- **KISS-минимум (рекомендую):** оставить замыкание, но дополнить условие
  inside-source-проверкой — нет, это четвёртая копия. Честный минимум —
  вариант Б.
- **Одна точка правды:** `PlanOutcome` получает `conflicts: HashSet<usize>`
  (индексы в `renames`) или `Rename.conflict: bool`, заполненные там же, где
  `validate_targets` ходит; замыкание в TUI удаляется. Заодно уходит
  per-keystroke `exists()` syscall из подсветки.

### 6. Два raw-mode-механизма в одном бинарнике

main.rs:136-169: hand-rolled termios через `libc` (структура-гвард `RestoreTermios`,
`unsafe`, аккуратные комментарии про ISIG/VMIN). Тем же бинарником уже поставляется
crossterm (tui.rs юзает `ratatui::crossterm`), у которого `terminal::enable_raw_mode()`
делает ту же работу — включая VMIN/VTIME — без `unsafe` и без прямого депенда libc.
По метрике «сложность = код, который поддерживаешь ты»: 35 строк unsafe-termios —
твои; crossterm — нет. Гвард восстановления пишется и там (или `crossterm::terminal`
плюс свой Drop в 5 строк). Поведение Ctrl-C-как-байта сохраняется — raw mode
crossterm тоже выключает ISIG. Мелкая находка, фикс по желанию.

## Мелочи

- **`u16`-скролл** (tui.rs:549): `(view.body.len() - 1) as u16` молча
  переполняется на >65535 строк превью — для массового renamer'а фотоколлекция
  на 70k файлов реальна, скролл сломается тихо. `scroll: usize` в App чинит.
- **`rebuild = true` безусловно** (tui.rs:274) — полный replan (match + validate +
  exists-syscall на строку) на каждое нажатие, включая стрелки скролла. Уходит
  само собой в фиксе находки 3.
- **O(n²) в `validate_targets`** (lib.rs:376-379): на каждую цель `find` по всем
  renames с `format!` в замыкании. На 1k файлов незаметно, на 10k — лаги
  превью на каждое нажатие. KISS-фикс если когда-нибудь заболит: для цели
  `a/b/c` проверить предков `a`, `a/b` по HashSet froms — O(depth) вместо O(n).
- **README: `$i` — "alphabetically"** — фактически побайтовый порядок
  (`match_paths` сортирует `String::cmp`): `"10 x.mp3" < "2 x.mp3"`, `"Z" < "a"`.
  Пользователь, перенумеровывающий коллекцию, наткнётся именно на это. Дешёвый
  фикс — слово «bytewise» в доке; natural sort в код не тащить.
- **Title `files: N`** считает и директории, и несматченных сиблингов — по сути
  «entries seen by the walk». Ни на что не влияет, просто знать.
- **Колесо мыши не скроллит список** — mouse-обработчик ловит только
  `MouseEventKind::Down`; Wheel уходит в холостой rebuild. Мелкий UX-пробел при
  включённом mouse capture.
- **Кончился `$$` → literal `$`**: `parse_replacement("$10")` = Group(1)+Literal("0") —
  задокументировано в README (`$1..$9`), тест есть. Ок, просто отмечено.

## Рекомендуемый порядок, если править

1. Строка `EmptyPatternSegment` — убрать висячую `(` (lib.rs:156-159).
2. `.pyc` из git + gitignore.
3. `poll(250ms)` → блокирующий `event::read()`; снести `rebuild`/`view: Option`
   каскадом (находка 3).
4. `plan_outcome` принимает `&[MatchedFile]` — чинит двойную работу в обоих
   лицах и порядок ошибок CLI (находка 4).
5. Конфликт-статус в `PlanOutcome`, удалить `conflicting()` из TUI (находка 5).
6. `read_key` → crossterm raw mode, убрать прямой `libc` (находка 6).
7. `scroll: usize` (мелочь).

Пункты 3-5 — «переписать, а не нарастить» в чистом виде: каждое удаляет
структуру, добавленную поверх вместо переделки, и уменьшает число строк.
